# GADS-SVD v0 (`src/gads_svd/detector.py`): соответствие модели и статус

Версия алгоритма: `gads-svd-v0.1-research`. Класс `GADSDetector`, параметры `GADSParams`. Тот же класс используется в API/веб-прототипе и в экспериментах (`tests/test_gads.py`, `src/evaluation/harness.py`).

**Статус: исследовательская конструкция, не валидирована.** Параметры по умолчанию — плейсхолдеры, на dev-seed не подбирались. Гипотезы H1–H5 не проверены; основная серия не запускалась; преимущество над baseline не показано (на единичных проверках механики — см. §3 — не наблюдалось).

## 1. Соответствие `docs/mathematical_model.md` (v0.1)

## 2. Отличия от модели v0.1 (сознательные, см. `research/protocol_amendments.md` A10)

1. Якорь отката фиксирован (burn-in / подтверждённый дрейф / откат); периодическое обновление контрольной точки через `K_cp` **не** используется.
2. Переякорение полное (`λ_drift=1`), буферы пересоздаются двухкратной перекрёстной подгонкой по окну.
3. Стратум с Δ включается только после накопления ≥ `m_min` значений в буфере Δ.
4. Подтверждение дрейфа — по пику доли срабатываний за эпизод тревоги и `p_confirm` окнам подряд (исправление дефекта логики, A10).
5. Не реализованы: учёт повторных появлений аккаунта вне соседних окон (Δ определена только для соседних окон), порог по полноте (`ω`-страты) — используется только разделение по наличию Δ.

## 3. Наблюдения механики на единичных запусках (НЕ результаты и НЕ основание для подбора параметров)

- Резкий дрейф (сценарий S1, seed 1000): конструкция переходит в DRIFT_SUSPECT в окне начала дрейфа и переякоривается на следующем окне.
- **Известный режим отказа на постепенном нормальном дрейфе** (демо S6, seed 1, 1000 аккаунтов; запуск `c0638efad4a9` в локальной базе): CUSUM пересекает порог (подозрение), подтверждения нет (модель успевает следовать за дрейфом, доля срабатываний мала), смещение от фиксированного якоря превышает `B_cum=0,5` → POISON_SUSPECT → заморозка → откат к устаревшему якорю → в окне 49 отмечено 294 из 1000 аккаунтов. Это предсказанный в `docs/mathematical_model.md` §6.3 риск «запирания/ложного отката». Изменения параметров или формул до процедуры dev-A/dev-B не вносились.
- В стабильных сценариях доля срабатываний среди нормальных близка к целевой α, а PR-AUC в единичном запуске ниже, чем у B2 (различия не оценивались статистически).

## 4. Что нужно для валидации

Пилот C на dev-seed (S0–S9), выбор `h_c, κ_c, B_cum, p_confirm, r_rollback, α_adm, λ_max, π_max` по dev-A с проверкой на dev-B, заморозка протокола, затем основная серия по `research/experiment_protocol.md`. До этого интерфейс помечает метод как «исследовательский · не валидирован».
