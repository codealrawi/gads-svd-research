# Веб-прототип социальной платформы GADS-SVD (`social_platform/`)

**Статус.** Локальный прототип для проверки **технической интеграции**: события платформы → временные матрицы → существующее ядро GADS-SVD и заранее выбранные базовые методы. Не медицинский сервис, не продукт; **не публиковался, реальные данные не собирались, исследовательский режим выключен по умолчанию**. Результаты на синтетических данных не доказывают эффективность на реальных медицинских платформах. Результат подтверждающего эксперимента J2 (K-I v1.3 `tracking` уступил `robust_ewpca_trim` при `δ = 0,02`) не изменялся и учитывается как есть.

## 1. Что это

| Часть | Файлы |
|---|---|
| Социальная лента (псевдонимы, публикации, комментарии, реакции, жалобы, правила, активность) | `social_platform/app.py`, `static/*` |
| Хранилище (SQLite, миграции, журнал, резервная копия) | `social_platform/db.py` |

| Режимы и «ворота» исследования | `social_platform/config.py` |
| События → окна → матрицы | `social_platform/windows.py` |
| Конвейер и адаптеры к ядру | `social_platform/pipeline.py` |
| Синтетические демо-данные | `social_platform/synthetic.py` |
| Операции (CLI) | `social_platform/cli.py` |
| Проверки | `social_platform/tests/test_platform.py` |

Существующий прототип анализа CSV (`src/api`, `src/ui`) **не изменялся**; новый пакет импортирует ядро (`src/*`) и два неизменённых защищённых модуля (`adaptive_spec/ki_gate_v1_3.py`, `adaptive_spec/e0_runner.py`).

## 2. Три режима (задаются окружением при старте, через веб-интерфейс не переключаются)

| Режим | Кто и что | Сбор исследовательских событий | Данные в алгоритм |
|---|---|---|---|
| `demo` | публичная демонстрация: только предсозданные синтетические аккаунты и публикации; посетитель только читает; регистрации и записи нет | **нет** (таблица событий содержит только `origin = synthetic`) | только синтетика |
| `local` | разработка/проверка: тестовые аккаунты с псевдонимом; лента работает | **нет** (события реальных аккаунтов не пишутся) | только синтетика |
| `research` | закрытый пилот совершеннолетних добровольцев; **запускается только** при верном файле подтверждений, флаге, базе, созданной в режиме `research`, и положительном сроке хранения | только у участника с **отдельным** активным согласием | участники — только после открытых «ворот» и ≥ 20 согласившихся |

«Ворота» исследования (`config.research_gate_problems`): режим `research`; `RESEARCH_MODE_ENABLED`; файл `RESEARCH_ACK_FILE` с заполненными ссылками (одобрение этического органа, форма согласия и её хэш, процедура удаления, владелец данных, протокол разметки, подписавший) и подтверждениями (`adults_only`, `minors_excluded`, `no_automatic_sanctions`, `separate_research_consent`, `withdrawal_and_deletion_procedure`, `storage_and_retention_rules_documented`); `retention_days > 0` и совпадает с `RESEARCH_RETENTION_DAYS`; база создана в `research`. Если условия не выполнены, приложение **не запускается** (до создания файла БД). База, созданная в `demo`/`local`, не может стать исследовательской (метка `created_mode` записывается один раз).

Принятие правил сообщества не является согласием на исследование: согласие — отдельная запись (`consents`), с подтверждением совершеннолетия и понимания цели; отзыв и удаление данных доступны участнику в любой момент.

## 3. Компоненты

```
Браузер ── HTTPS (прод: Caddy) ──> FastAPI (1 процесс, uvicorn)
                                      ├─ static/        SPA без CDN, DOM только через текстовые узлы
                                      ├─ app.py         API, сессии/CSRF, ограничение частоты, заголовки CSP
                                      ├─ db.py          SQLite (WAL), миграции, журнал, backup/verify
                                      ├─ windows.py     события → матрицы окон (минимальные признаки)
                                      └─ pipeline.py    методы на ОДНИХ И ТЕХ ЖЕ окнах:
                                           src.evaluation.harness.run_method + REGISTRY (B0, B2, GADS v0)
                                           adaptive_spec.KIv13 (tracking), e0_runner.RobustEWPCA   [без изменений]
```

## 4. База данных (миграция 1)

| Таблица | Назначение (содержимое) |
|---|---|
| `meta`, `schema_version` | режим создания БД, версия схемы |
| `users`, `sessions` | псевдоним, хэш пароля (scrypt), роль; сессии (хранится только хэш токена и CSRF) |
| `posts`, `comments`, `reactions`, `reports` | лента; жалобы со статусом и решением модератора |
| `audit_log` | административные/системные действия (идентификаторы и счётчики; без паролей и текстов) |
| `consents` | исследовательское согласие участника (версия, выдано, отозвано) |
| `research_events` | **только** `(event_id, account_id, origin, event_type, ts)`; без текста |
| `synthetic_truth` | метки генератора синтетики (только для оценки, алгоритму не передаются) |
| `runs`, `run_methods`, `run_scores` | запуски: конфигурация, хэш входа, хэши кода, статус по методам, оценки |

## 5. События, окна, признаки

События (только при активном согласии в режиме `research`, либо `synthetic`): `post`, `comment`, `reaction`, `report`. Без телеметрии клиента, без времени пребывания, без содержимого. Окно — `WINDOW_HOURS` (по умолчанию 24 ч). Признаки аккаунта в окне (6): `posts`, `comments`, `reactions`, `reports`, `active_slots` (число различных часов с событиями), `max_hour_burst` (максимум событий за час). Правила (проверены детерминированно): дубликаты `event_id` считаются один раз; неизвестные аккаунты/типы и события вне диапазона отбрасываются и учитываются в счётчиках; конец окна исключается; неактивный аккаунт даёт нулевую строку, а не пропуск; порядок событий не влияет на результат; хэш входа записывается в запуск.

## 6. Интеграция и методы

Одни и те же окна подаются всем методам (парный план): `static_svd` (B0), `forgetting_pca` (B2), `gads_v0`, `ki_v13_tracking` (V13Params по умолчанию, режим `tracking`, `declared_assumption` → пометка «допущение не проверено» в записи запуска), `robust_ewpca_trim`. В запуск записываются версии, `config_hash`, хэши файлов кода, параметры окон, счётчики событий и ошибки. Сбои метода записываются, метод останавливается, запуск помечается `done_with_method_errors`.

Фиксированные параметры платформы: для `static_svd` и `forgetting_pca` `energy = 0,80` (значение по умолчанию 0,90 даёт ранг 4 при 5 активных координатах, правило `ω ≥ k + 2` не выполняется и оценки не определены; найдено при первом локальном запуске; это техническое ограничение, не подбор по качеству).

Результаты — **сигналы для проверки человеком**: ни блокировки, ни скрытия, ни санкции алгоритмом не применяются (проверено тестом). Модерация — решение человека по жалобе.

## 7. Безопасность (реализовано)

Пароли — scrypt, минимум 10 символов, разные регистры и цифра; сессионный токен — случайный, в БД только хэш; cookie `HttpOnly`, `SameSite=Strict`, `Secure` по настройке; CSRF-токен и обязательный заголовок запроса, проверка `Origin`; ограничение частоты (общее и для входа); лимит размера тела; санитаризация текста, запрет e-mail/телефона/ссылок в публикациях; CSP `script-src 'self'`, `frame-ancestors 'none'`, `nosniff`, `no-store` для API; админ-эндпоинты только для роли `admin`; журнал административных действий без секретов; секреты только из окружения; резервная копия с проверкой целостности и числа строк; удаление и экспорт данных участника.

## 8. Запуск и проверки (локально)

```bash
# окружение проекта (.venv), из корня репозитория
set PLATFORM_MODE=demo & set PLATFORM_DB=data_local/demo.sqlite3
python -m social_platform.cli init-db
python -m social_platform.cli seed-demo
set ADMIN_PSEUDONYM=admin_local & set ADMIN_PASSWORD=<пароль для одной команды>
python -m social_platform.cli create-admin
python -m uvicorn social_platform.app:create_app --factory --host 127.0.0.1 --port 8100
python -m pytest social_platform/tests -q -p no:cacheprovider
```

## 9. Ограничения

Один процесс, SQLite, ограничение частоты в памяти; демонстрационный масштаб. Сборка Docker-образа и развёртывание не проверялись. Админ — единственная роль с панелью; роль модератора не вынесена отдельно. Синтетический генератор простой (малая размерность, низкий ранг, один тип аномалии), поэтому результаты на нём описывают проверку интеграции. Вопросы юридического соответствия, обработки медицинских сведений и этики **не решены** и требуют компетентных специалистов (см. `docs/social_platform_research_readiness_checklist.md`).
