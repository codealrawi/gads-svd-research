# Baseline-методы B0–B5: соответствие протоколу, доступные данные, ограничения

Версия 0.1 (2026-10-09, КТ4). Код: `src/baselines/`, оболочка и калибровка — `src/evaluation/harness.py`, метрики — `src/evaluation/metrics.py`.

## 1. Соответствие утверждённому протоколу (`research/experiment_protocol.md` §1.1)

| ID протокола | Метод | Класс | Статус | Отличия от протокола |
|---|---|---|---|---|
| B0 | статический truncated SVD | `StaticSVD` | реализован | обучение на первых 10 окнах burn-in; окна 10–19 — hold-out для замороженного порога (A5) |

## 2. Какие данные доступны методу на каждом шаге

| Шаг | Метод получает | Не получает |
|---|---|---|
| `fit_burn_in` | `WindowView` первых 10 окон (`t, ids, X`) | метки, `T0`-границу тестовых окон, будущие окна |
| `score(w_t)` | `w_t` и внутреннее состояние, построенное по окнам `< t` | метки любых окон, окна `> t`, пороги |
| `update(w_t)` | `w_t` после оценки | метки |
| калибровка порога | оценки *всех* прошлых окон самого метода | оценки текущего окна, метки |

Идентификаторы аккаунтов в B0–B5 не используются (нет состояния на аккаунт). Следовательно, появление/исчезновение аккаунтов влияет только через состав выборки окна.

## 3. Ограничения адаптации

| Метод | Адаптация | Ограничение |
|---|---|---|
| B0 | нет | не следует за дрейфом по построению; порог заморожен |
| B1 | полный пересчёт по последним `W` окнам | включает аномальные и отравляющие наблюдения без отбора; запаздывает на ≈ `W/2` окон; ранг пересчитывается по энергии 90 % |
| B2 | экспоненциальное забывание (полураспад 10 окон) | без отбора и без отката; подвержен «boiling frog» по построению; ранг фиксирован |
| B2′ | то же, но с усечением на `k` | отбрасывание «хвоста» меняет оценку при близких собственных значениях; нули вместо пропусков |
| B3 | нет памяти модели, рефит на стеке 3 окон | трансдуктивна (текущее окно участвует в своей подгонке); при плотном шуме `S` не разрежена, `λ=1/√max(n,d)` не настраивается |
| B4, B5 | рефит на `W=10` прошлых окнах | пропуски заменяются центром (без индикатора) — ослабляет методы при пропусках; нет отбора обучающих точек |

Потоковый режим для B3, B4, B5 не определён: используется рефит по окнам (rolling re-fit), а не онлайновое обновление; это зафиксировано в имени и описании метода.

## 4. Оценка и калибровка

Общая для всех методов процедура (`harness.run_method`): перед окном `t` порог вычисляется по буферу оценок окон `< t`; буфер содержит оценки **всех** аккаунтов (конечные значения); веса `2^{−возраст/10}`; уровень квантиля `⌈(m_eff+1)(1−α)⌉/m_eff`, `α = 0,05`.

Последствия (проверены тестами `tests/test_leakage.py`):
- чистый буфер и обмениваемые нормальные оценки дают номинальный FPR (≈ 5 %);
- доля `π` аномалий в буфере с оценками выше порога делает FPR среди нормальных ≈ `(α−π)/(1−π) < α` (консервативно) и снижает полноту; при `π ≥ α` порог попадает внутрь распределения аномалий (FPR ≈ 0, полнота низкая);
- калибровка на «допущенных» (обрезанных сверху) оценках занижает порог и завышает FPR — поэтому не применяется;
- при дрейфе буфер и тест необмениваемы, и гарантия номинального FPR не действует; реализованный FPR измеряется и публикуется;
- B0: порог заморожен после hold-out; при дрейфе его FPR растёт — это свойство метода, а не ошибка калибровки.

Правило ранга для B0–B2′ (энергия ≥ 90 %) на данном генераторе даёт `k = 6` при истинном ранге 3 (A6); последствия — рост доли `insufficient` (`ω < k+2`) при пропусках. Порог не меняется.

## 5. Строки с недостаточными данными

Оценка определена при `ω ≥ k+2` (SVD-семейство) или `ω ≥ 3` (B3, B4, B5). Остальные строки получают `NaN`, не флагуются, не участвуют в калибровке и в метриках качества; их доля `insufficient_frac` публикуется отдельно в каждой таблице.
