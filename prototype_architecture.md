# Архитектура веб-прототипа (версия 0.1, КТ5)

Цель: локально запускаемый, контейнеризуемый MVP обнаружения аномального поведения аккаунтов, который использует **то же ядро** (`src/data`, `src/baselines`, `src/gads_svd`, `src/evaluation`), что и эксперименты. Прототип — демонстрационный: он не блокирует аккаунты, не выдаёт выводы о нарушениях и не содержит результатов основной научной серии.

## 1. Что найдено в проекте (аудит окружения)

| Объект | Состояние |
|---|---|
| Язык / окружение | Python 3.12.13, `.venv` в проекте, зависимости зафиксированы `pip freeze` (`requirements.txt`) |
| Ядро | `src/data/synthetic_generator.py`, `src/baselines/*` (B0–B5), `src/gads_svd/{subspace_alignment,detector}.py`, `src/evaluation/{harness,metrics}.py`; 138 тестов |
| Уже используемый веб-стек | **нет** (в этом проекте). В старых папках (`Downloads\medplatforma-*`) есть FastAPI-платформа с `admin/admin123` в README и автоматической записью `is_anomalous` — **не переиспользуется** и не затрагивается |
| Docker / Node | на этой машине не установлены → сборка контейнера здесь не проверяется (см. §7) |
| Git | не установлен |

## 2. Выбранная архитектура

```
Браузер ── HTTPS ──> Caddy (прод, авто-TLS)  ──> приложение (FastAPI + uvicorn, 1 процесс)
                                                   ├─ src/ui/static/*   SPA без сборки (HTML/CSS/JS)
                                                   ├─ src/api/*         маршруты, валидация, очередь заданий
                                                   ├─ ядро (src/*)      тот же код, что в экспериментах
                                                   └─ SQLite + npz-файлы  (volume /data)
```

- **Один контейнер приложения + опциональный Caddy** (профиль `prod`). Микросервисов нет: нагрузка — единицы пользователей, вычисления — секунды–минуты.
- **Backend: FastAPI.** Почему: ядро на Python/NumPy — прямой вызов без межъязыковой границы; автоматическая валидация запросов и OpenAPI; лёгкие тесты `TestClient`. Альтернативы отвергнуты: Streamlit (слабый контроль над API/безопасностью/историей запусков и сложнее ставить за Caddy), Django (избыточно), отдельный Node-фронтенд (нет Node, лишняя сборка).
- **Frontend: статическая SPA (ES-модули), без сборки и без CDN.** Графики рисуются собственным SVG-модулем (`charts.js`), поэтому нет внешних запросов и зависимости от интернета; CSP `script-src 'self'`. Интерфейс на русском; все тексты в словаре `i18n/ru.json` + функция `t(key)` — добавление `en.json` не требует изменения кода.
- **Хранение: SQLite (WAL) + `.npz`-файлы данных.** Почему: один маленький сервер, нет отдельного сервиса БД (нечего выставлять наружу), простое резервное копирование (`sqlite3 .backup` + копия каталога `datasets/`). Миграции — нумерованные SQL-скрипты в `src/api/db.py` (таблица `schema_version`); Postgres можно подключить позже, интерфейс хранилища изолирован в `db.py`.
- **Фоновые задания:** `ThreadPoolExecutor(max_workers=1)` внутри процесса; состояние в таблице `runs` (ожидание → выполнение → завершено/ошибка) с долей прогресса; при перезапуске незавершённые задания помечаются прерванными. Очередь ограничена. Отдельный брокер (Celery/Redis) не нужен на этом масштабе.
- **Доступ:** необязательный общий токен доступа (`GADS_ACCESS_TOKEN`): если задан, все `/api/*`, кроме `/api/health`, требуют заголовок `X-Access-Token`; интерфейс запрашивает токен один раз (хранится в `sessionStorage`). Для публичной демонстрации токен задаётся в `.env` (в репозиторий не попадает). Учётных записей и паролей нет.

## 3. Модули

| Файл | Роль |
|---|---|
| `src/api/config.py` | настройки из окружения, лимиты (размер файла, строк, аккаунтов, окон) |
| `src/api/db.py` | SQLite, миграции, фабрика соединений |
| `src/api/csv_io.py` | строгая проверка и разбор CSV (без выполнения кода, без pandas-эвалюации) |
| `src/api/algorithms.py` | реестр алгоритмов: название, версия, схема разрешённых параметров, валидация, фабрика → класс из ядра |
| `src/api/services.py` | наборы данных, запуск анализа, сводки, карточка аккаунта, сравнение, экспорт |
| `src/api/main.py` | FastAPI: маршруты, заголовки безопасности, статические файлы |
| `src/ui/static/` | `index.html`, `app.css`, `app.js`, `charts.js`, `i18n/ru.json` |

Поток анализа: загрузка/генерация → `datasets` + `.npz` → `POST /api/runs` → поток выполнения строит `WindowView` → `harness.run_method(detector, …, hook)` (**тот же префиксный цикл**, что в экспериментах) → строки результатов в `scores` → сводка → экспорт. Метки (если есть) используются только после анализа для блока «оценка по меткам» через `evaluation.metrics.run_metrics` и подписываются как «метки симулятора/файла, не экспертная разметка».

## 4. Разделение режимов

Каждая запись помечена `mode`: `demo` (встроенные синтетические данные) или `user` (загруженный CSV). Интерфейс всегда показывает режим бейджем; на главной панели явно указано, что **результаты основной научной серии здесь не отображаются и не смешиваются** (серия не запускалась; результаты будут храниться в `results/`, отдельно от БД прототипа).

## 5. Безопасность (меры, реализованные в коде)

- Загрузка: расширение `.csv`, лимит размера (потоковое чтение с обрывом), UTF-8, запрет NUL, строгая схема заголовка и значений, лимиты строк/аккаунтов/окон; данные никогда не исполняются и не `eval`-ятся.
- Идентификаторы аккаунтов — только `[A-Za-z0-9_.-]{1,64}` (псевдонимы; адреса почты и т. п. отклоняются), имена признаков — `[A-Za-z][A-Za-z0-9_]{0,39}`.
- Экспорт CSV защищён от «формульных» инъекций (экранирование ведущих `= + - @`).
- Параметры алгоритмов — только из белого списка с диапазонами.
- Заголовки: `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, `Cache-Control: no-store` для API; интерфейс строит DOM через `textContent` (без `innerHTML` с данными).
- Ограничение размера JSON-тел, очереди заданий, ошибок без трассировки наружу.
- Секреты — только через окружение; `.env.example` без значений; БД и файлы данных не публикуются (volume, не за прокси).
- В демонстрации только синтетические данные; реальные персональные/медицинские данные не включены.

## 6. Ограничения прототипа

- Не рассчитан на многопользовательскую работу и большие данные (лимиты в `config.py`); один рабочий поток.
- Алгоритм GADS v0 — исследовательская конструкция с невалидированными параметрами (см. `docs/gads_v0_implementation.md`); результаты не являются научным доказательством.
- Оценка аномальности ≠ доказательство мошенничества; статусов «бот/нарушитель» в системе нет.
- Нет учёток пользователей; один общий токен (опционально).
- Не проверялись: сборка Docker-образа и Caddy на этой машине (нет Docker), нагрузка, браузеры кроме встроенного.

Инструкции — `docs/deployment_timeweb.md`. Фактическая проверка docker-сборки здесь невозможна (Docker не установлен), поэтому в отчёте статус — «файлы подготовлены, не собраны».
