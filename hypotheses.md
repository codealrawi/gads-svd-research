# Гипотезы (версия КТ3, v0.1 — фиксируются ДО основного запуска)

Статус: предрегистрируемый документ. Пороги успеха, метрики и тесты ниже установлены до просмотра каких-либо результатов экспериментов (результатов ещё нет — генератор и baseline не реализованы). Любое изменение после пилота оформляется в `research/protocol_amendments.md` с датой, причиной и указанием, были ли просмотрены результаты тестовых seed.

Сокращения: **B0** статический SVD, **B1** скользящий SVD, **B2** забывающее потоковое подпространство (вариант B модели), **C** исследовательская конструкция GADS (вариант C, `docs/mathematical_model.md` §5.3), **C−Gk** — абляции. Сценарии S0–S9 и baseline — `research/experiment_protocol.md`.

## Общие правила для всех гипотез

- **Единица репликации** — один независимый прогон (seed). Аккаунто-окна внутри прогона зависимы и не считаются независимыми наблюдениями. Методы сравниваются на одних и тех же seed (парные разности).
- **Seed-пулы:** dev `1000–1999` (только настройка гиперпараметров и пилот), test `2000–2999` (основной запуск, одноразово). Результаты test не используются для изменения порогов.
- **Неопределённость:** 95 % доверительные интервалы — перцентильный bootstrap по прогонам (10 000 повторов, BCa при n ≥ 20). Для долей — Клоппер–Пирсон по прогонам.
- **Тесты:** парный критерий Уилкоксона (двусторонний, α = 0,05) для разностей; направление эффекта указано в критерии успеха заранее. Поправка Холма внутри семейства сравнений каждой гипотезы (семейства не объединяются; это ограничение: общее число проверок по гипотезам `m_total` публикуется, а интерпретация H1–H5 дополнительно сопровождается скорректированными по Бонферрони p при `m_total`).
- **Число прогонов** `n`: определяется *после пилота* (10 dev-прогонов на ячейку) по формуле `n = ⌈1,05·((z_{1−α/(2m)} + z_{0,8})·σ_d/δ)²⌉` (мощность 0,8, `σ_d` — SD парной разности в пилоте, `δ` — минимальный значимый эффект из критерия успеха), с границами `30 ≤ n ≤ 200`; значение фиксируется в `protocol_amendments.md` до запуска test.
- **Реализованный FPR (Tier 1)** должен лежать в `[0,5α; 1,5α]`, иначе метод в этой ячейке помечается `FPR-violation`, а его сравнение выполняется по Tier 2 (TPR при заданном FPR на тестовых нормальных, *оракульная* метрика качества ранжирования). Обе метрики публикуются.
- **Интерпретация:** «подтверждена» — выполнены все пункты критерия успеха; «не подтверждена» — эксперимент выполнен корректно, но критерий не выполнен; «не проверена» — эксперимент невозможен/невалиден (данные, ошибки). Отрицательный результат публикуется.

## H1. Задержка обнаружения при сопоставимом FPR

- **Содержание:** адаптивный метод (B2 и C) обнаруживает внезапно возникшие аномальные аккаунты быстрее, чем статический SVD (B0), при сопоставимой доле ложных срабатываний, когда нормальное поведение дрейфует.
- **Переменные:** независимая — метод ∈ {B0, B1, B2, C}; сценарий ∈ {S1 (резкий дрейф нормы), S2 (постепенный дрейф), S6 (совместный дрейф + аномалии)}, контроль — S0. Зависимая — задержка `D`.
- **Основной показатель:** `D` = среднее по аномальным эпизодам прогона числа окон от момента появления аномалии до первого срабатывания; пропуск — значение горизонта `H = 10` (ограниченное среднее).
- **Порог для основной метрики:** Tier 2, FPR = 5 % (порог методa подбирается на нормальных аккаунтах тестовых окон прогона; оракульный относительно меток нормальных, но не использует метки аномалий).
- **Baseline:** B0 (основной); B1, B2 — вторичные сравнения.
- **H0:** `E[D_{B0} − D_{M}] ≤ 0` для M ∈ {B2, C}. **H1_alt:** `> 0`.
- **Критерий успеха (до запуска):** для M = C (и отдельно для M = B2) в каждом из S1, S2, S6: средняя парная разность `D_{B0} − D_M ≥ 1,0` окна, нижняя граница 95 % ДИ > 0 и скорректированное p < 0,05; **и** в S0 `D_M − D_{B0} ≤ 0,5` окна (верхняя граница 95 % ДИ ≤ 0,5). H1 подтверждена, если условие выполнено в ≥ 2 из 3 дрейф-сценариев для M = C; при выполнении только для B2 формулируется как «адаптация вообще, без защиты».
- **Ограничения интерпретации:** синтетика с известной причиной дрейфа; B0 при сильном дрейфе деградирует по FPR (его Tier 1 нарушит допуск) — поэтому задержка берётся по Tier 2; задержка зависит от величины аномалии и каденции окон; выводы для реальной платформы не следуют.

## H2. Защищённое обновление уменьшает деградацию при постепенном отравлении

- **Содержание:** при постепенном изменении поведения подозрительной когорты (boiling frog, сценарий S4) защищённое обновление C теряет в обнаружении «пробной» аномалии меньше, чем незащищённое B2.
- **Переменные:** метод ∈ {B2, C, C−G1, C−G2, C−G4/G5}; фактор — наличие/отсутствие отравляющей когорты (S4 vs тот же seed без когорты — «чистый двойник» S4_clean); размер когорты `φ ∈ {0,02; 0,05; 0,10}`.
- **Основной показатель:** деградация `Deg_M = TPR_M(S4_clean) − TPR_M(S4)`, где TPR — доля *пробных* аномалий (свежая когорта целевого профиля, окно `T_p`), помеченных при Tier 2 FPR = 5 %.
- **Baseline:** B2 (основной); B0, B1 и ANTIDOTE-подобный робастный baseline (B6) — вторичные.
- **H0:** `E[Deg_{B2} − Deg_C] ≤ 0`; **H1_alt:** `> 0`.
- **Критерий успеха:** при `φ = 0,05` медианная разность `Deg_{B2} − Deg_C ≥ 0,10`, нижняя граница ДИ > 0, скорректированное p < 0,05; **и** non-inferiority: в S0 и S3 разность `TPR_C − TPR_{B2}` имеет нижнюю границу 95 % ДИ > −0,03. Вторичный (не входит в критерий): C vs B6.
- **Ограничения:** реальный эффект атаки задан симулятором, адаптивный противник, знающий модель, не моделируется (только «наивная» дрейфующая когорта); результаты относятся к `φ ≤ 0,10`. Утверждение 2 (границы влияния) не доказательство эффективности.

## H3. Адаптивный выбор ранга улучшает компромисс качество/затраты

- **Содержание:** правило ранга по краю Марченко–Пастура с гистерезисом (M6) не хуже лучшего фиксированного ранга при постоянной структуре и лучше его при смене внутреннего ранга.
- **Переменные:** правило ранга ∈ {адаптивное MP, фиксированный `k` (выбран на dev), энергия ≥ 90 % (старая работа)}; сценарии S9 (смена ранга), S0, S1, S7.
- **Основной показатель:** PR-AUC на объединённых тестовых аккаунто-окнах прогона. Вторичный: время обработки окна (медиана, мс), `tracemalloc`-пик.
- **Baseline:** фиксированный ранг (лучший на dev), энергия-90.
- **H0:** `E[PRAUC_{адапт} − PRAUC_{фикс}] ≤ 0` в S9; **H1_alt:** `> 0`.
- **Критерий успеха:** в S9 разность ≥ 0,02 (нижняя граница ДИ > 0, скорректированное p < 0,05); в S0, S1, S7 non-inferiority с запасом 0,01 (нижняя граница ДИ > −0,01). Часть «затраты»: если разность времени/памяти меньше шума измерения (при `d ≈ 12`, это ожидаемо), заявляется «затраты не различимы», а не выигрыш.
- **Ограничения:** выбор лучшего фиксированного `k` на dev даёт ему преимущество знания структуры; «энергия-90» — воспроизведение старого правила; вычислительный выигрыш при малом `d` ожидаемо пренебрежим.

## H4. Перенос с синтетики на медицинскую тематическую выборку

- **Содержание:** порядок методов на синтетике (по основной метрике PR-AUC) частично воспроизводится на health-related данных.
- **Данные:** Davoudi et al. (2020) — условно (§ ниже); Cresci-17 — отдельная проверка общей переносимости (не медицинская).
- **Основной показатель:** коэффициент ранговой согласованности Кендалла `τ` между порядками методов (по PR-AUC) на синтетике и на реальных данных; число методов ≥ 5.
- **H0:** `τ ≤ 0`; **H1_alt:** `τ > 0`. **Критерий успеха:** `τ ≥ 0,6` и нижняя граница bootstrap-ДИ по оценкам методов > 0.
- **Условие проверяемости (проверяется до любых вычислений):** данные получены на законных основаниях (лицензия/условия использования проверены), содержат ≥ 30 размеченных аномалий (bot), ≥ 3 временных окон с метками времени активности и достаточно признаков для построения `X_t`. Для набора Davoudi это **не подтверждено**: в статье сказано о выпуске кода и обучающей выборки на healthlanguageprocessing.org, но состав (есть ли временные метки твитов, или только агрегированные признаки), лицензия и условия Twitter/X не проверены. Если условие не выполнено — **H4 помечается «не проверена»**, а не «не подтверждена».
- **Ограничения:** метка «bot» в Davoudi включает организации и неличные аккаунты; признаки статические; ни один из этих наборов не проверяет клиническую пользу; перенос на *другую* платформу невозможен без отдельных данных.

## H5. Различение нормального дрейфа и постепенного отравления

(Дополнительная гипотеза по требованию КТ3; формулируется отдельно, так как H2 измеряет только последствие, а не различение.)

- **Содержание:** режимный детектор C (M10–M11, §6) отличает массовый нормальный дрейф (S2) от отравляющей когорты (S4) при одинаковом смещении истинного подпространства и реагирует соответственно.
- **Переменные:** сценарий ∈ {S2, S4} с согласованной величиной дрейфа (одинаковое конечное `d_sin` между начальным и конечным истинными подпространствами нормы: `0,3; 0,6; 0,9`), метод ∈ {C, правило «только `d_sin`», B2 (без режимной логики)}.
- **Основной показатель:** сбалансированная точность `BA = (TPR_{дрейф} + TPR_{отравление})/2`, где «верный исход» в S2 — достигнуто DRIFT_CONFIRMED без ROLLBACK и без запирания; в S4 — достигнуто POISON_SUSPECT/ROLLBACK до пробного окна `T_p` без DRIFT_CONFIRMED.
- **Вторичный показатель:** отсутствие запирания: в S2 после подтверждения дрейфа + 5 окон реализованный FPR (Tier 1) ≤ 1,5·α.
- **H0:** `BA_C ≤ 0,5` (случайное различение); **H1_alt:** `BA_C > 0,5`.
- **Критерий успеха:** `BA_C ≥ 0,80` при нижней границе 95 % ДИ ≥ 0,70 на test-seed по трём величинам дрейфа; `BA_C − BA_{«только d_sin»} ≥ 0,10` (нижняя граница ДИ > 0), т. е. статистика доли превышений медианы добавляет к скорости движения подпространства; вторичный показатель выполнен.
- **Baseline-ожидание:** B2 всегда адаптируется и не имеет режимов; BA определена как 0,5 по конструкции (показатель для него не оценивается, чтобы не создавать тривиальное «превосходство»); сравниваются C и «только `d_sin`».
- **Ограничения:** различение опирается на единственную посылку (A_π: меньшинство <20 % аномалий); при >50 % когорте или имитации массового дрейфа метод по конструкции не различает; результат относится к одному механизму отравления (линейный дрейф когорты к целевому профилю).

## Гипотезы, которые заранее признаны непроверяемыми на имеющихся данных

- Клиническая/модерационная польза, выводы о «нелегитимности» аккаунтов — не проверяются никаким планируемым экспериментом.
- Устойчивость к целенаправленной адаптивной атаке — не заявляется (в протоколе нет адаптивного противника с доступом к модели).

## Что остаётся неразрешённым

1. Конкретные значения `h_c, κ_c, B_cum, p, r, α_adm, λ_max, h` фиксируются на dev; их выбор не должен «подгоняться» под критерии H2/H5 на тех же dev-seed без отдельной валидации (разделение dev на dev-A (настройка) / dev-B (проверка перед заморозкой)).
2. Достаточность консервативной калибровки по буферу «всех оценок» при высокой доле аномалий (π ≥ α) — измеряется (Tier 1), но критерий допуска [0,5α; 1,5α] может не выполняться для всех методов; тогда сравнение идёт по Tier 2.
3. Для H4 нет подтверждения доступности данных.
